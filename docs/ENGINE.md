# 기록·재생 엔진 분석 및 미구현 경계

이 문서는 0.1.0 시점의 초기 분석 기록입니다. 0.2.0에서 추가한 실험용 네이티브 엔진과 현재 검증 범위는 [ENGINE_NATIVE.md](ENGINE_NATIVE.md)에 정리했습니다.

## 확인한 근거

설치된 `KingdomUnderFire.exe`는 x86 PE, 8,352,688 bytes입니다. 파일 버전은 `1,0,0,1`, SHA256은 `69f2575ad14c78d3c6f7c15d0187234be005f06abf095d3f1bd602f1c3722868`입니다. 이 해시는 **분석 대상 식별값**이며 검증된 재생 지원 빌드 목록이 아닙니다.

`tools/analyze_game.py`는 파일을 읽기만 합니다. 문자열, 실행 섹션의 주소 상수 후보, 일부 역어셈블, PE import를 `game-analysis.json`에 기록합니다. 후보 참조를 찾을 때 임의 위치에서 디코딩한 문맥은 명령 경계가 틀릴 수 있어 단독으로 함수 증거로 사용하지 않습니다.

추가로 명령 경계를 확인한 `0x4fa0a3..0x4fa11c` 구간에서는:

- `0xb8a280`을 `[esi+0x44]`와 비교합니다.
- `g_RandSeed` 로그 직전 `0xbed1e8` 및 `[esi+0x3c]`를 읽고 둘을 비교합니다.
- `g_RandomCount` 로그 직전 `0xb827dc` 및 `[esi+0x40]`를 읽고 둘을 비교합니다.
- 비교 후 `[esi+0x3c]`, `[esi+0x40]`를 두 전역 위치에 씁니다.

로그와 인접 명령은 난수 동기화 상태 비교·복원을 뒷받침합니다. 마지막 전역의 역할과 경기 단위 초기화, 모든 RNG 사용처, 틱 경계는 동적 검증이 필요합니다. 위 주소는 이 파일의 정적 분석에만 사용했고 후킹에 사용하지 않았습니다.

`EventTCPIPCmdQueue`의 요청·노드 변경·데이터 청크·동기화 관련 로그, `SYNC:[Frame:%d][MyChecksum:%d][ReceivedChecksum:%d]`, `have/recv tick/rndSeed/rndCnt`도 존재합니다. 동기화 명령 큐 후보는 있지만 직렬화 형식과 게임 명령/관전 입력 구분은 확정하지 않았습니다. 설치 폴더에는 `.kfm` 지도들과 `save/seo/user2.dat`가 있습니다. 사용자 설정 파일을 경기 상태 스냅샷으로 취급하지 않았습니다.

## 방식 비교와 결정

명령 재생은 데이터가 작고 해상도와 분리할 가능성이 있지만, 경기 시작 상태·자원·슬롯·규칙·RNG·명령 순서·틱을 전부 복원해야 합니다. 네트워크 패킷 녹화만으로 충분하다는 근거는 없습니다. 위 동기화 구조를 우선 추적하는 것이 다음 단계입니다.

게임 저장 기능 기반 상태 스냅샷은 완전한 직렬화/복원 경계가 확인되면 유용합니다. 현재 저장 파일과 객체 복원 함수가 확인되지 않아 사용할 수 없습니다. 프로세스 전체 메모리 덤프는 포인터, 소켓, DirectDraw/사운드 핸들 및 런타임 자원 때문에 다른 PC에서 안전한 복원이 보장되지 않습니다. 화면 영상 녹화는 재현은 가능해도 자유 관전·타 플레이어 정보 요구사항을 만족하지 못합니다.

따라서 **결정론적 명령 재생 가능성은 미확정**입니다. 최소 동일 경기 재현이 검증되기 전 관전자 후킹을 구현하지 않았습니다. 런처에는 재생 어댑터를 설치하거나 외부 실행 코드를 읽는 기능이 없습니다.

## 구현된 컨테이너 경계

`.kufreplay`는 데이터 전용 ZIP입니다. 정확히 `manifest.json`, `initial.bin`, `commands.bin`, `rng.bin`, `checksums.bin`, `map.bin`만 허용합니다. `format_version=1`, `complete=true`, 기록 시각, 게임 버전/해시, 규칙 버전/해시, 어댑터 식별, 지도 식별/해시, 틱 수/주기와 각 데이터 SHA256을 검증합니다. 최대 압축/해제 합계 256MiB, 메타데이터 64KiB, 항목 중복·암호화·심볼릭 링크·알 수 없는 압축·높은 압축률을 거부합니다. 파일을 게임 폴더에 풀거나 포함 파일을 실행하지 않습니다. 해시는 진위를 인증하지 않고 바이트 손상을 검사합니다.

바이너리 데이터의 의미 구조는 게임 어댑터가 확정되어야 정의할 수 있습니다. 지금의 구조 검증은 재생 가능성 검증이 아니며 모든 리플레이가 UI에서 미지원으로 표시됩니다. 테스트용 바이트를 실제 경기 리플레이로 제공하지 않습니다. 지도 바이트 저장 공간은 구현했지만 지도 의존 리소스 전체를 수집·복원하는 기능은 미구현입니다.

가져오기는 크기를 제한하며 `.partial`에 복사 → 복사본 검증 → 영구보관 설정 저장 → atomic rename 순서입니다. 저장 전 flush/fsync를 수행합니다. 영구보관 이외의 항목만 최신 기록 시각 기준 정책으로 정리합니다. 목록/해시/가져오기/업데이트는 UI와 분리한 작업 스레드에서 수행합니다. 게임 호스트 안에는 기록 작업이 전혀 없습니다. 향후 실제 엔진 연결 시 별도 프로세스 큐의 용량 제한과 넘침 시 기록 실패 표시를 추가해야 합니다.

## 다음 검증 게이트

1. 초기 상태 직렬화, 슬롯·지도·규칙 초기화, 모든 RNG 사용처와 틱 진행 함수 확인.
2. 명령 디코딩/적용 경계와 네트워크 순서를 연결하여 실제 경기에서 틱별 체크섬을 비교. UI 입력 없이 같은 결과 재현.
3. 명령 큐만으로 부족하면 완전한 상태 스냅샷을 추가. 초기·주기 체크섬 불일치 시 명확히 중단.
4. 시야·탐지·선택·이펙트·사운드의 표시 경계를 각각 확인. 게임 상태와 관전자 상태를 분리하고 RAII 복원 및 패치 구간/원본 바이트 검증 구현.
5. 관전자 캐시 갱신, 진영별 인구·농부·진행 상태, I/U, 배속과 렌더 분리, 로딩/Esc, 종료 확인 구현.
6. 멀티플레이 호스트 부하, 모든 진영·투명/공중/지하·지도 전환·다른 해상도·외부 PC 실경기 검증.

현재 게임을 실행하거나 실제 경기 입력을 조작하지 않았습니다. 위 게이트, 관전자 전체, 게임 로직 호환 재생, 후킹 무결성 및 모든 종료 경로 복원은 미검증·미구현입니다.
